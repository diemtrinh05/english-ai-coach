
# 2. UX Product Principles

## 2.1. Learning First

Mỗi màn hình phải giúp user trả lời:

```text
Tôi nên làm gì tiếp theo?
```

## 2.2. One Primary CTA

Mỗi màn hình chỉ có một hành động chính.

## 2.3. AI Is Supportive

AI xuất hiện thông qua:

```text
Recommended for you
Based on your recent practice
High priority
Personalized practice
```

Không hiển thị technical AI details cho learner.

## 2.4. Motivation Without Pressure

Ưu tiên:

```text
Great job
Keep going
You're improving
```

Tránh:

```text
You failed
Bad score
Wrong again
```

# 5. Critical UX Distinction — Daily Plan vs Review

This distinction is mandatory.

## Today's Plan

Answers:

> “Hôm nay tôi nên làm gì?”

It is generated by the Personalization Engine and constrained by the user's time budget.

Example:

```text
Today's Plan
7 new words
18 reviews
5 quiz questions
Estimated: 20 min
```

## Review Tab

Answers:

> “Hiện tại tôi có những từ nào cần ôn?”

The Review Tab can contain more due words than today's recommended workload.

Example:

```text
Review
32 words currently due

Today's plan selected:
18 words
```

Therefore:

```text
Daily Plan
= personalized recommendation

Review
= complete due-review queue
```

# 12. Answer Quality UX

Recommended labels:

```text
Forgot
Hard
Difficult
Okay
Easy
Very Easy
```

Internal mapping:

```text
Forgot      → 0
Hard        → 1
Difficult   → 2
Okay        → 3
Easy        → 4
Very Easy   → 5
```

This wording should be usability-tested because “Hard” and “Difficult” are close in meaning.

# 13. SRS Feedback

Example:

```text
Nice work!

Next review
in 17 days
```

Never claim:

```text

```

Reason:

```text
SRS schedules the next review;
it does not guarantee memory.
```

# 21. Connectivity Model

V1 is **online-first**.

## Online

```text
Full learning functionality
Submit attempt
SRS update
Quiz submission
Personalized Exercise
```

## Offline

```text
Cached read-only content where available
No learning mutation
No offline queue
No automatic sync
```

Offline message:

```text
No internet connection

Please reconnect to continue learning.

[Retry]
```

---

# 22. Offline UX Rule

Do not promise:

```text
Your learning data will sync later.
```

Do not simulate:

```text
Offline Attempt
→ Local Queue
→ Background Sync
```

in V1.

---

# 24. Error Handling

```text
401 → session refresh/login
403 → permission error
404 → content unavailable
409 → refresh/retry current state
429 → rate limit / AI budget
503 → service unavailable
```

Never expose raw Java/SQL exceptions.

---

# 25. AI Failure UX

If Personalized Exercise cannot be generated:

```text
Personalized practice isn't available right now.

You can continue with standard practice.

[Try Standard Practice]
```

This preserves learning continuity.

# 29. UX Acceptance Criteria

```text
[ ] User understands today's task within seconds.
[ ] Home has one clearly primary CTA.
[ ] Daily Plan and Review have distinct meanings.
[ ] User can start the Daily Plan from Home.
[ ] New Words activity uses the Daily Plan target.
[ ] Review tab exposes the due-review queue.
[ ] Flashcard flow is understandable without instructions.
[ ] Answer Quality is understandable.
[ ] Client never asks for isCorrect.
[ ] SRS result is understandable without technical detail.
[ ] Personalized Exercise clearly communicates personalization.
[ ] Progress can be scanned quickly.
[ ] Weak Word reasons are understandable.
[ ] Offline state never promises auto-sync.
[ ] Network-required actions are blocked while offline.
[ ] User can recover from errors.
[ ] AI failure has a learning fallback.
[ ] Navigation is consistent.
```

# Reconciled V1 Contract Binding

UI behavior must bind to Android Technical Specification v1.1 and API/OpenAPI v1.4. Daily Plan is a stable persisted snapshot (including aggregate QUIZ item); assessment/SRS/personalization/gamification are backend authoritative; V1 is online-first; notification uses FCM/device preferences; all learner-facing copy is Vietnamese.
